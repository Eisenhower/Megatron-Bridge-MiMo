MiMo-V2-Flash · verl 适配迁移到 Megatron-Bridge

变更说明（相对 main 已有的 MiMo-V2-Flash 适配 #3163） · 生成于 2026-06-02
一句话总结： main 上已有的 #3163 提供了 MiMo-V2-Flash 的基础桥接（结构、权重映射、FP8 反量化加载）。 本次工作在此基础上，把 verl 的 RL 训练适配语义对齐进来（MoE 路由、attention value 缩放、attention-sink 冻结）， 补齐了 训练 recipe 与 recipe 单测，并通过远程 GPU 实测验证了 HF↔Megatron 前向数值一致性（cosine ≈ 0.999）。同时论证并确认 Megatron-LM 无需任何改动。

1. 背景与目标

目标是把 verl 中对 MiMo-V2-Flash 的 Megatron 训练适配迁移进 Megatron-Bridge，后续通过 “verl 集成 Megatron-Bridge” 的方式做该模型的 RL 训练（verl 官方推荐路径）。约束：

  • 不集成 FP8 训练代码（保留把开源 FP8 权重反量化为 BF16 加载的必需路径）。
  • 凡 verl 与 main 行为有差异，以 verl（经真实 RL 训练验证的配置）为准；但实现方案必须合理。
  • 判定 Megatron-LM 这部分代码应集成进 Bridge 还是保留在 Megatron-LM。

3. 逐项详解

3.1 MoE 路由对齐 verl 真值（bridge）

MiMo-V2-Flash 是 256 专家、top-8、sigmoid 打分的细粒度 MoE（DeepSeek 风格 noaux_tc）。把路由参数显式设为 verl 经训练验证的取值：

-        provider.moe_router_pre_softmax = True
+        provider.moe_router_score_function = "sigmoid"   # 显式，不再隐式依赖 HF scoring_func
+        provider.moe_router_pre_softmax = False          # sigmoid 打分，top-k 取原始分数
+        provider.moe_router_bias_update_rate = 0.0       # 冻结 e_score_correction_bias（RL 不在线更新）
+        provider.moe_router_dtype = "fp32"               # 256 专家 + sigmoid 需 fp32 路由保数值稳定
         provider.moe_router_load_balancing_type = "none"
         provider.moe_router_enable_expert_bias = True

依据：verl models/mcore/mimo_v2_flash/config_converter.py 路由段逐字段一致。

3.2 attention_value_scale 应用到 V（modeling）

MiMo-V2-Flash 在注意力中对 V 整体乘以常数 attention_value_scale（如 0.707）。在 QKV 非对称切分之后、进入 TE 注意力之前折到 V 上：

+        value_scale = getattr(self.config, "attention_value_scale", None)
+        if value_scale is not None:
+            value = value * value_scale

与 verl core_attention.py（value = value * attention_value_scale）及 vLLM 推理一致； 由于注意力对 V 是线性的，“切分后乘 V”与“注意力入口乘 V”数值等价。

3.3 attention-sink bias 冻结（provider）

sink bias 是预训练标定值，RL 阶段必须冻结，否则噪声梯度会破坏滑窗注意力分布。Bridge 走 TE 原生 softmax_type="learnable"，对应参数名 core_attention.softmax_offset：

+    freeze_attention_sink_bias: bool = True
+    # provide() 内、建模完成后：
+    if self.freeze_attention_sink_bias:
+        for name, param in model.named_parameters():
+            if name.endswith("softmax_offset"):
+                param.requires_grad = False

依据：verl attention.py 中 attention_sink_bias = nn.Parameter(..., requires_grad=False)。

3.4 死代码清理 / 防双重缩放（modeling）

原 MiMoV2FlashTEDotProductAttention.__init__ 中保留了一行只赋值不使用的 self._attention_value_scale， 会误导维护者以为 core attention 里也应用了 value_scale（实际只在 §3.2 应用一次）。改为明确注释，避免未来“双重缩放”bug：

-        self._attention_value_scale = getattr(config, "attention_value_scale", None)
+        # NOTE: attention_value_scale 已在 get_query_key_value_tensors 对 V 应用过
+        # （匹配 verl/vLLM）。不要在此再次应用，否则会双重缩放。

3.5 训练 recipe（新增）

recipes/mimo_v2_flash/mimo_v2_flash.py 提供 3 个 BF16 配置：pretrain / sft / peft(lora|dora)， 统一应用 MoE/attention kernel 设置（transformer_engine + alltoall + grouped GEMM + permute fusion，且关闭 force-load-balancing 以保 RL/推理一致）。 不含任何 FP8 训练 recipe/config/param。RL 经 verl 直接经 AutoBridge 驱动模型，不依赖这些 recipe。

5. 关键技术判断

5.1 Megatron-LM 无需改动 （已论证 + 实测）

verl 当年改 MLM 是因为走自研 PyTorch-SDPA 路线、需把逐层配置透传进 TransformerConfig。Bridge 走 TE 原生 + 子类化路线即可覆盖全部所需语义：

verl 在 MLM 加的东西Bridge 的等价承载
attention sink bias（自研模块/开关）TE 原生 softmax_type="learnable" 的 softmax_offset（HF 官方也是“sink 作为额外 softmax 列再丢弃”的 off-by-one 写法，二者等价）
per-layer RoPE theta（253 行 registry）MiMoV2FlashRotaryEmbedding 双 base（SWA 用 local、full 用 global），同 Gemma3 模式
per-layer KV heads / 非对称 V子类逐层切换 num_query_groups；TE 的 k_channels/v_channels 承载非对称 V
滑窗TE window_size（见 5.3）

符合 Bridge “不改 3rdparty/Megatron-LM、模型专属逻辑只放 model family 目录” 的规范。本地独立的 Megatron-LM 仓保持零改动。

5.2 attention_value_scale：三方一致性 （已确认）

该参数在 verl、vLLM、Bridge 中均应用 value * 0.707。小米 MiMo 官方此前的 HF modeling 一度遗漏了它，现已补齐。三方对齐，Bridge 实现正确。

5.3 滑窗 window：Bridge 比 verl 更贴合官方实现

HF 官方 modeling 用 transformers 的 sliding_window_causal（sliding_window=W ⇒ 每个 query 关注 W 个 key）。 Bridge 用 window_size=(W-1, 0) = W 个 key，与 HF 一致； verl 用 (W, 0) = W+1 个 key，是 verl 侧的一个 off-by-one。故此处保留 Bridge 现状（更准），未刻意复制 verl 的偏差。

5.4 routed_scaling_factor：自动与 vLLM/HF 一致 （已确认）

该值在当前权重 config 中为 null，Bridge 经 CONFIG_MAPPING 后等效 1.0（与 HF/vLLM 默认一致，已被含 MoE 层的 parity 实测覆盖）。 若将来真实模型设为非 1.0，Bridge 会自动取该值并应用，仍与 vLLM/HF 对齐。无需改动。
